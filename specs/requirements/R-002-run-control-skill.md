# R-002：运行中人工控制与长期工作流 skill 沉淀

- 状态：confirmed（2026-11-25，用户确认五个默认值）
- 优先级：P1
- 提出人 / 日期：用户 / 2026-11-25
- 决策人：用户
- 关联任务：待建（建议 T-21 运行控制、T-22 skill 沉淀）
- 关联 ADR：待建（运行控制状态机与 skill 生命周期）

## 1. 背景与问题

治理任务（巡检、单次扫描、全量扫描）在审批通过后长时间自动运行，管理员发现方向偏差时只能等待或取消，无法暂停、补充引导后继续。同时同类任务反复执行相同的检索与推理，每次都重新查资料，token 消耗高、耗时长；现有 `main-context.ts` 的 `skills` 只是管理员手工维护的受控文件，没有管理端增删、版本与生效控制，无法沉淀可复用的工作流。

## 2. 目标与场景

管理员在治理任务运行中发现偏差时，可让运行在当前 step 边界暂停，追加引导词后继续或取消；同类任务结束后可把有效路径沉淀为 skill，下次任务优先复用，减少重复检索与输入 token。

可观测结果：固定样本下重复检索调用次数与单任务输入 token 明显下降，任务成功率不下降。

## 3. 范围（做）

1. 运行控制：治理任务与管理员聊天支持 pause / resume / cancel；暂停为边界暂停（当前 step/工具调用跑完，下一步模型调用前挂起）；暂停期间可追加引导词，下一次模型调用前注入；30 分钟无人处理自动取消并释放槽位；控制命令持久化、跨实例生效并写审计。
2. skill 沉淀：任务结束或管理员手动触发时生成“待发布”提案；管理员可列表、新增、编辑、启停、删除、发布；skill 含适用条件、步骤序列、提示要点、检查清单与阈值；带版本号，运行中读取固定版本；注入上限 3 条 / 4000 字符，先摘要后按需展开。
3. 交付面：后端管理与内部接口、Agent 消费与注入、管理端最小页面（skill 管理 + 运行详情暂停/继续/追加引导）。

## 4. 非范围（不做）

- 不承诺中断已发出的模型请求；不支持在任意语句内插队。
- 不覆盖学生/教师会话，不允许管理员暂停或向其注入引导词。
- 不做 skill 自动发布；不做向量化 skill 检索与效果看板。
- 不做完整控制台（版本对比、提案审核流、跨任务分析）。
- 不改造计费系统；不做生产多实例容量压测（归部署验收）。

## 5. 验收标准

| # | 场景 | 操作 | 期望结果 | 证据 |
| --- | --- | --- | --- | --- |
| 1 | 边界暂停 | 治理任务运行时管理员点暂停 | 当前 step 完成后停在下一步模型调用前，状态 paused，运行记录可见 | 集成测试 + 管理端截图 |
| 2 | 继续与取消 | 暂停后点继续 / 取消 | 继续从断点执行且计划不重跑已完成步骤；取消进入终态并释放槽位 | 集成测试 |
| 3 | 追加引导 | 暂停中提交引导词后继续 | 下一次模型调用上下文包含引导；审计含 trace、操作者、内容摘要 | 单测 + 审计查询 |
| 4 | 超时收敛 | 暂停后 30 分钟无操作 | 自动取消、释放槽位、运行记录标记超时 | 定时任务测试（假时钟） |
| 5 | skill CRUD | 管理员新增/编辑/启停/删除 | 成功且版本递增；非管理员 403；每次操作写审计 | pytest / vitest |
| 6 | 提案与发布 | 任务结束生成提案，管理员发布 | 发布前不注入；发布后按版本生效；可回滚到旧版本 | 集成测试 |
| 7 | 注入上限 | 命中超过 3 条或 4000 字符 | 按优先级截断并记录被截断条目，不超预算 | 单测 |
| 8 | 量化收益 | 20 条固定治理样本 A/B | 重复检索调用 -50%，输入 token -30%，成功率不降，P95 不劣化 | 对比报告 |
| 9 | 回归 | 开关关闭或未命中 skill | 行为与当前一致，无额外模型调用 | 全量回归 |

## 6. 约束

- 性能与延迟：暂停/继续接口 P95 < 300ms（不含模型）；注入使首 token 延迟增加 ≤ 200ms。
- 并发与容量：控制命令跨实例生效，必须带运行版本/租约 fencing；同一运行并发命令只允许一个生效；暂停最多保留槽位 30 分钟。
- 安全与隐私：仅 admin 可操作；引导词与 skill 不得含密钥、Cookie、隐私原文；skill 不构成授权依据；所有控制、注入、CRUD 均记 trace 与操作者。
- 成本：单次注入 ≤ 3 条 / 4000 字符，额外 token 默认上限 1500；超限截断。
- 部署与兼容：`RUN_CONTROL_ENABLED`、`SKILL_INJECTION_ENABLED` 默认关闭；不新增外部服务依赖；表结构变更走 Alembic。

## 7. 依赖与风险

- 依赖：后端新表与 `/api/governance/*` 管理接口、`/internal/agent/*` 只读接口；Agent plan executor 检查点与聊天注入点；管理端页面；现有槽位租约与 trace。
- 最大未知：暂停期间占用槽位对其他任务排队的影响；多实例租约与续租冲突；skill 注入对模型稳定性的影响。
- 失败回退：关闭两个功能开关即回到现状；skill 停用即停止注入；控制命令失败保留原运行状态并返回明确错误。

## 8. 优先级与决策

- 优先级理由：提升治理效率与可干预性，不阻塞发布。
- 发布阻塞关系：不阻塞 F-C6、T-18 与真实环境验收。
- 谁确认：用户。
- 可延期项：完整控制台、效果看板、向量化 skill 检索、跨任务收益分析。

## 9. 可行性初判（助手填写）

- 现有能力与限制：已有审批等待 `read/resume/cancel`、运行取消、`main-context.ts` 的受控 skills、`experiences` 提案与发布路径；缺运行中暂停状态机、引导词注入通道、管理端 CRUD 与版本控制。暂停只能停在 step 边界。
- 可选方向：A 控制面优先；B 沉淀优先；C 同批做。用户选择 C。
- 推荐最小切片：单个治理任务的 pause + guidance 闭环；skill 的最小 CRUD + 发布后注入；管理端最小页面。
- 需要先验证的假设：step 边界检查点能覆盖计划执行器全部路径；暂停 30 分钟不阻塞其他任务；20 条样本能代表真实任务分布。
