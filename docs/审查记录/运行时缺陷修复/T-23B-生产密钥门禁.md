# T-23B 生产密钥门禁

日期：2026-11-27
范围：R-003 / ADR-012 / BUG-002（P0）

## 设计依据

- `specs/requirements/R-003-runtime-defect-fixes.md` 第 3 节与第 9 节：生产启动必须阻断默认/弱 JWT 密钥；非 root 数据库账号不是本期必须项，但数据库密码必须有强度。
- `docs/decisions/ADR-012-运行时缺陷修复.md` 第 2 条：`debug=False` 时强校验，Compose 缺变量即失败。
- `.trae/rules/coding-style.md`：小步冒烟 + 所属服务 lint。

## 验证记录

- `uv run pytest tests/test_config_prod_guard.py -q` → 4 passed。
- `uv run ruff check app/core/config.py tests/test_config_prod_guard.py` → All checks passed。
- 未设置变量执行 `docker compose -f deploy/docker-compose.prod.yml config --quiet` → 退出码 1，提示 `required variable MYSQL_ROOT_PASSWORD is missing a value`。
- 设置强密钥与强数据库密码后同样命令 → 退出码 0。
- 覆盖场景：开发态允许默认值；生产态拒绝默认 JWT、31 字节 JWT、`root` 密码、短密码；强配置通过。

## 决策说明

- 校验放在 `Settings` 的 `model_validator(mode="after")`，在应用导入阶段触发；生产容器因此启动即失败，而不是带弱密钥运行。
- JWT 同时检查“非默认值”和“≥32 字节”，覆盖默认值本身长度已过 32 的情况。
- 数据库密码用 `urlsplit` 解析，避免正则误判；解析失败按空密码处理并拒绝。
- Compose 使用 `${VAR:?message}`，缺失时在 `docker compose config/up` 阶段失败；healthcheck 复用同一变量，避免容器内回退。
- 非 root 应用账号按用户决定不纳入本期，保留为后续加固项。
- 未验证：真实生产容器启动（本机仅验证 Compose 解析与应用配置单测）。
