# P0-3 长任务可恢复：聊天可恢复流

日期：2026-11-20
范围：聊天 SSE 断线/换实例续接、重复提交幂等、主动取消；先覆盖 chat，不引入 Redis。

## 设计依据

- 架构评审 P0-3：聊天运行与 HTTP 连接绑定，`stream.onAbort(control.cancel)` 会在断线时取消运行，换实例后无法续接，用户重试还会重复消耗模型。
- 用户确认：可恢复流先覆盖 chat；沿用 P0-1 的 MySQL 方案，不引入 Redis 或新框架依赖。
- `AGENTS.md` 硬性约束：Agent 不直连业务 MySQL，只调用 `/internal/agent/*` 白名单接口；接口字段蛇形；不落密钥、Cookie 与隐私原文。
- `specs/plan.md` AX-R09 / `specs/spec.md` SA-R03：运行、工具与审计必须可追踪；子 Agent 外部执行在沙箱边界内。
- `.trae/rules/conventions.md`：统一响应 `{ code, data, message }`；错误文案中文；文档与术语简体中文。
- 现有实现：`governance/router_internal.py` 已有 ServiceAuth + CurrentUser 双凭证用户级接口；Agent `routes/chat.ts` 当前一次发送完整 delta；`loop/run-control.ts` 提供 180 秒运行预算与取消。

## 实现

### 后端（FastAPI + MySQL）

- `governance/models.py`：
  - `AgentChatStream`：`user_id`、`request_id`、`agent_run_id`、`trace_id`、`status`、`cancel_requested`、`expires_at`、`created_at`；唯一 `(user_id, request_id)`。
  - `AgentChatStreamEvent`：`stream_id`、`seq`、`event_type`、`payload`（原始 SSE data JSON）；唯一 `(stream_id, seq)`。
- `governance/schemas.py`：创建、事件追加、快照、续接读取、追加回执均 `extra=forbid`；事件类型限定 `meta/delta/notice/done/error`，单条 200 KB。
- `governance/service_internal.py`：
  - 30 分钟 TTL；读/写前机会式清理该用户过期流与事件。
  - 创建幂等：已有同用户同请求 id 直接返回，不覆盖原 `agent_run_id`；并发唯一冲突回滚后重读。
  - 追加：序号必须连续；重复序号同内容幂等、不同内容 409；`done → succeeded`，`error → cancel_requested ? cancelled : failed`；终态后拒绝追加。
  - 读取与取消均按 owner 过滤，他人的/过期的/未知的一律 404。
- `governance/router_internal.py`（ServiceAuth + CurrentUser）：
  - `PUT /internal/agent/user/chat-streams/{request_id}`
  - `POST /internal/agent/user/chat-streams/{request_id}/events`
  - `GET /internal/agent/user/chat-streams/{request_id}?after=N`
  - `POST /internal/agent/user/chat-streams/{request_id}/cancel`
- `alembic/versions/p0c_chat_streams.py`：接 `p0a_agent_slot_leases`，建两张表、唯一约束与索引，可回滚。

### Agent

- `internal-client.ts`：新增 4 个聊天流方法；请求 id 统一小写 UUID；校验后端回显 id、回执序号与读取游标不回退；`data` 保持原始字符串。
- `chat/event-store.ts`：先持久化再通知本地订阅者；序号由 Agent 分配；持久化失败立即关闭订阅并抛出，不广播未落库内容。
- `chat/registry.ts`：按 `(用户, request_id)` 同步占位，同实例并发只创建一个运行；登记项 30 分钟，过期在下次访问时机会式清理，不额外使用定时器。
- `chat/sse.ts`：
  - 本地订阅从 `after` 回放后等待新事件；修复“终态恰好落在本轮快照之后”被跳过的竞态。
  - 跨实例续接每 500 ms 轮询后端，原样回放 `id:` 游标，直到终态或 200 秒截止；截止不伪造 done。
  - 单次 SSE 写入 5 秒截止；投递失败只结束连接，不改写运行结果。
- `routes/chat.ts`：
  - `request_id` 可选，缺省生成并写入 meta。
  - 运行信号与 HTTP 请求解耦：使用独立 `createRunControl`，180 秒预算；槽位 `lease.signal` 启动后并入运行信号（管理端终止仍生效）。
  - 双客户端：运行客户端绑定运行信号（工具/审计），持久化客户端独立于运行信号，取消后仍能写入 error 终态。
  - 首次创建才启动运行；已有流只回放/订阅，不再调用模型。运行每 1 秒读取后端 `cancel_requested` 兜底跨实例取消。
  - `GET /agent/chat/runs/:requestId/stream?after=N`：未知/过期返回 404 中文；否则续接回放。
  - `POST /agent/chat/runs/:requestId/cancel`：先落后端取消标记，再中止本地运行；未命中本地运行也返回已记录，由轮询兜底。

### 前端

- `src/api/agent-chat.ts`：
  - 始终发送 `request_id`；解析 SSE `id:` 游标。
  - 未收到 done 且连接结束：按 `after=lastSeq` 自动 GET 续接，最多 3 次、总时限 200 秒；404 透传中文“已过期或不存在”。
  - 用户中止：不续接，独立于中止信号异步 POST cancel。
  - 续接复用同一组 `onDelta`，游标之前的 delta 不会重复展示。

## 决策说明

- 采用“后端事件表 + Agent 本地缓冲”双层：本实例订阅走内存低延迟，跨实例/换实例走 MySQL 回放；不引入 Redis。
- `(user_id, request_id)` 唯一，客户端生成 request_id；其他人复用同一 id 也只会得到 404，避免越权读取。
- 已有 running 流不重启模型：宁可等待其 180 秒预算结束，也不重复消耗模型；残留 running 由 30 分钟 TTL 收敛。
- 持久化失败必须关闭订阅：避免“页面显示成功但记录不存在”；后端写入不可用时无法补写终态，这是已知边界。
- 前端只在传输中断时续接，服务端 error 事件直接展示，不自动重试，避免把明确失败包装成重试循环。
- 运行客户端与持久化客户端分离：取消会中止模型与工具，但不能中止写终态；否则取消会丢掉 cancelled/error 记录。

## 遗留与限制

- delta 仍是整段答案一次性发送，续接粒度较粗；逐 token 透传不在本次范围。
- 运行实例崩溃后，流保持 running 直到 TTL，不做跨实例接管（避免重复模型调用）。
- 后端事件追加失败时无法写终态，流会保持 running 至过期；前端提示中断并停止续接。
- 前端自动续接上限 3 次 / 200 秒；超过后提示“回复中断，请重试”。
- 只覆盖 chat；结构化任务（doc_draft、suggest_tags 等）仍为一次性请求，可按同一事件模型扩展。
