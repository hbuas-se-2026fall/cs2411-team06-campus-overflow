# P0-1 多实例准入与跨实例租约

日期：2026-11-20
范围：后端 `agent_slot_leases` 与内部租约接口、Agent 租约客户端、治理全局准入、夜间整理跨实例互斥。

## 设计依据

- 架构评审 P0-1：进程内 8 槽与本地 `running` 标记在多实例下失效，夜间任务会重复执行。
- 用户确认方案：MySQL 租约队列，条件更新原子 claim，复用现有 MySQL，不引入 Redis。
- `specs/plan.md` AX-R09：8 槽是单实例上限，多实例叠加；治理全局去重需要独立机制。
- `.trae/rules/conventions.md`：内部接口只在 `/internal/agent/*`，服务 token 鉴权、trace id 透传。

## 实现

### 后端

- 新表 `agent_slot_leases`（迁移 `p0a_agent_slot_leases`）：`(kind, slot_no)` 复合主键、`owner_instance`、`job_id`、`fencing_token`、`lease_expires_at`。
- 接口：
  - `POST /internal/agent/slot-leases/claim`：容量内原子占用；过期或本人持有的槽位可复用；满返回 409「全局槽位已满」。
  - `POST /internal/agent/slot-leases/{kind}/{slot_no}/renew`：token 匹配且未过期才续租，否则 409。
  - `POST /internal/agent/slot-leases/{kind}/{slot_no}/release`：token 匹配才释放。
- 释放采用删除并在容量内取最小空闲编号，避免编号空洞导致容量失真；容量下调后超出编号的旧行不占新配额。
- 插入竞争由复合主键兜底，冲突回滚后重试最多 5 次。

### Agent

- `backend-lease.ts`：租约客户端与 `createGovernanceAdmission`；409 解释为“繁忙”而非网络错误，不重试。
- `AgentPool`：配置 `AGENT_GLOBAL_GOVERNANCE_LIMIT > 0` 时，治理任务先申请跨实例准入，再进入本地治理队列；拒绝抛 `PoolBusyError`，路由返回 503。问答任务不申请全局租约（按设计保持每实例 5 槽）。
- 夜间整理：`AGENT_GLOBAL_MAINTENANCE_LIMIT`（默认 1）申请 `maintenance` 租约，job 为 `nightly:<UTC 日期>`；抢不到或后端不可用则跳过本次，不重复执行。租约 TTL 900 秒，释放失败只记录日志，由 TTL 兜底。

## 决策说明

1. 只对治理任务做全局准入：问答按产品设计保持“每实例 5 槽”，全局化会改变已确认的容量语义；如需全局问答配额，可复用同一租约接口另配 kind。
2. 先申请全局租约再排队本地槽位：实现简单，但等待本地槽位期间也占用全局名额；容量应配置为不低于实例数 × 3。
3. 夜间互斥使用同一套租约而非新增调度表：减少一套状态机；TTL 900 秒未做自动续租，超过 15 分钟的整理存在被抢占风险，后续可加心跳续租。
4. 释放失败不反噬任务结果：由 TTL 回收，避免“任务成功但接口报失败”。

## 遗留

- chat 流仍为每实例容量，未做跨实例全局问答配额。
- 未做真实双实例并发验收；本轮为 SQLite 单测 + 本地 MySQL 迁移。
- 治理全局准入默认关闭（`AGENT_GLOBAL_GOVERNANCE_LIMIT=0`），需部署时显式开启。
- 夜间租约未接自动续租与 fencing 校验（续租接口已具备，调度器暂未使用）。

## 修订（2026-11-20，P0-5）

- 原“过期或本人持有即可抢占”收紧为“已过期，或同一 `job_id` 的重试”：同实例的其他任务不得顶替未过期租约，否则全局容量会被本进程绕过。
- 影响面：直接 claim 与排队晋升共用同一回收规则；同一 job 重试仍复用原槽位并轮换 `fencing_token`，旧 token 续租/释放返回 409。
- 2026-11-20 P0-6 补充：同一 job 的顶替/重试受 `retry_count` 限制（初始 5，每次 -1，归零后拒绝），并允许跨实例同 job 接管；详见 [P0-6租约重试预算.md](./P0-6租约重试预算.md)。
- 边界（P0-6 起已放宽）：实例重启后 `instance_id` 变化时，同一 job 现在可跨实例接管（消耗 1 次重试预算）；不再需要等待 TTL 到期。
