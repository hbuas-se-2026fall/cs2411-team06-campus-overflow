# P0-2 沙箱策略层与容器运行时边界

日期：2026-11-20
范围：Agent 外部执行策略层、agent-browser 执行接线、MCP 沙箱强化、新增容器运行时沙箱。

## 设计依据

- 架构评审 P0-2：现有 `agent/Dockerfile.sandbox` + `deploy/mcp-sandbox/docker-compose.yml` 是普通 Docker，bridge 默认可出网，不构成真正的执行边界。
- `specs/spec.md` SA-R03：子 Agent 的命令、外部工具与高风险操作必须在沙箱边界内执行，不直接访问业务数据库。
- `specs/plan.md` AX-R09：子 Agent 为同进程逻辑隔离单元，外部执行统一走沙箱；进程内不持有业务数据库连接。
- `AGENTS.md` 硬性约束 2/3/5：高风险动作须审批；MCP 工具白名单；run/tool call 必须留 trace id 与摘要。
- `.trae/rules/coding-style.md`：用户可见文案中文、错误码英文；不记录密钥与隐私原文；工具白名单注册。
- 现有实现：`security/{contracts,hooks}.ts` 已有工具网关失败关闭语义，`tools/execution-gateway.ts` 负责审批与 hook；`web/public-fetch.ts` 已有 SSRF 防护；`web/browser-reader.ts` 是唯一外部进程入口。

## 实现

### 策略层（`agent/src/sandbox/`）

- `contracts.ts`：策略、执行请求、决策、审计事件与固定原因码；`SandboxPolicyError` 只携带原因码。
- `policy.ts`：
  - 工作区限定：可执行文件必须是绝对路径；`cwd` 必须落在配置根目录内，先 `resolve` 再比较，`/tmp/worker` 不会命中 `/tmp/work`。
  - 命令白名单：文件名大小写不敏感，支持 `agent-browser-*` 前缀；硬禁用列表优先于允许列表，写 `*` 也不能放行 shell、解释器、下载与远程工具。
  - 参数上限：条数、单参数长度，拒绝 NUL/CR/LF；执行器固定 `shell: false`，不把 `&` 等字符当 shell 语法。
  - 网络：`none` / `loopback` / `allowlist` 三档；allowlist 按点边界匹配子域，`evil-example.com` 不会命中 `example.com`。
  - 审批：`read` 直接放行；`write`/`network` 必须携带非空 `executionId`，否则 `approval_required`。
  - 超时按策略上限收敛；取消信号在启动前直接拒绝。
  - 环境变量只保留白名单键，凭证类变量不会进入子进程。
- `executor.ts`：
  - 唯一外部执行入口；策略拒绝时不启动进程、不重试、不降级。
  - 启动前 `realpath` 复核 `cwd`，防止检查后被符号链接替换。
  - `execFile` + `shell: false` + `SIGKILL` + `maxBuffer`；超时、取消、输出超限、底层失败统一映射为固定原因码，不把 stderr 或命令行带回上层。
  - 审计事件只含工具名、文件名、16 位命令摘要、参数个数、动作类型、网络模式、trace id、耗时与输出字节，不含参数正文、URL 或错误消息。
- `config.ts`：默认失败关闭——工作区为系统临时目录、只允许 `agent-browser-*`、网络 `none`、输出 1 MiB、超时 30 秒；环境变量只能追加白名单，不能移除硬禁用列表。

### 接线

- `web/browser-reader.ts`：默认执行器改为 `runSandboxed`，`ReaderInvocation` 增加 `traceId`；浏览器 CLI 只允许回环桥接，仍不继承服务、模型、代理或浏览器凭据。
- `web/tools.ts`：`readWebPage` 把 `context.traceId` 传入浏览器读取，保证外部执行可追溯。
- `DEFAULT_ENV_ALLOW_KEYS` 显式保留 `AGENT_BROWSER_SOCKET_DIR`，避免剥离后会话目录退化。

### 容器

- `deploy/mcp-sandbox/docker-compose.yml`：新增 `runtime: ${MCP_SANDBOX_RUNTIME:-runc}`（生产设 `runsc` 启用 gVisor）、`memswap_limit`、`nofile: 512`，`/tmp` 追加 `nodev`。
- 新增 `deploy/sandbox-runner/docker-compose.yml`：命令/浏览器/文件执行的容器运行时沙箱——`network_mode: "none"`、只读根、非 root 65534、`cap_drop: ALL`、`no-new-privileges`、512 MiB / 1 CPU / 128 PID、`/tmp` 与 `/workspace` 均为 `noexec,nosuid,nodev` tmpfs、不挂载宿主目录、不注入凭证。
- `deploy/mcp-sandbox/README.md`、`deploy/sandbox-runner/README.md`、`deploy/README.md` 同步隔离项、gVisor 验证方式与未完成边界。

## 决策说明

1. 不新增通用命令工具：当前产品只需要只读网页读取，策略层先覆盖唯一外部进程。新增命令工具时必须复用 `runSandboxed`，并进入 `sandbox-runner` 容器，不允许宿主直接 `spawn`。
2. 硬禁用列表不允许通过环境变量移除：`SANDBOX_DENY_EXECUTABLES` 只追加；shell 与通用解释器在宿主进程层等价于任意代码执行，不能只靠提示词约束。
3. 不拒绝 `&`、`|` 等字符：执行器固定 `shell: false`，这些字符只是普通参数；只拒绝会破坏审计与参数边界的 NUL/CR/LF。若未来引入 shell，必须先改策略再放开。
4. 网络在进程层是“声明 + 审计”，真正断网由容器 `network_mode: "none"` 保证；本机策略层无法阻止任意子进程开 socket，因此不把它写成已强制隔离。
5. 审计当前只写结构化日志：P0-4 再接入后端持久化；现在保证事件字段足够且不泄密。
6. `sandbox-runner` 默认 `runc` 便于本地校验，生产必须显式 `SANDBOX_RUNTIME=runsc`；未验证 gVisor 前不宣称已启用。
7. MCP 沙箱仍需访问 FastAPI，不能改成 `network none`；出站白名单继续由部署侧防火墙/代理收敛，文档已写明。

## 遗留

- `sandbox-runner` 尚未接入任何真实工具；接入前容器本身不产生执行流量。
- 本机 Docker 引擎未启动，gVisor 与资源上限均未做真实运行验证，仅配置级校验。
- 本机策略层无法强制内存上限，`maxMemoryMb` 目前只作为容器侧声明。
- 审计未持久化，也未纳入现有 `agent_runs`/工具调用记录（P0-4）。
- 网页读取仍必须使用回环桥接，因此该进程不能跑在完全断网的 `sandbox-runner` 中；这是当前产品形态的已知例外。
