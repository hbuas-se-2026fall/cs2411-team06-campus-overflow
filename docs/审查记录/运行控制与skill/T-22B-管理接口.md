## 决策说明

- 编辑语义：存在草稿就原地更新内容；没有草稿（当前版本已发布）时新建 `max(version)+1` 草稿。这样发布过的版本内容永不改写，历史运行引用的版本保持稳定。
- 发布语义：缺省发布最新草稿并置 `current_version`；指定 `version` 时执行回滚，仅允许「已发布」版本，且不改写该版本 `published_by/published_at`。回滚后 `status=active`。
- 归档即删除：`DELETE` 只把 `status` 置为 `archived`，不级联删除版本；归档后拒绝编辑、启停与发布，避免恢复后状态含义不明。
- 启用前置条件：`current_version` 必须存在，避免「active 但无内容可注入」；`disabled` 可在任意已发布状态下使用，作为快速停用手段。
- 权限与审计：复用 `require_roles("admin")`，`get_current_user` 已拦截 banned；每次创建/编辑/发布/回滚/启停/归档写 `action_logger` 摘要，日志不含 skill 正文。
- 并发：版本递增与发布在 `SELECT ... FOR UPDATE` 的 skill 行锁内完成，避免两个管理员同时编辑产生重复版本号；SQLite 测试忽略行锁但不影响单连接断言。
- 分层：新增 `repository_skill.py` 只返回普通字典；`pyproject.toml` 补充 `repository_skill -> models` 白名单与 service/repository 非 Web 依赖契约，`lint-imports` 保持 5 条全绿。
- 遗留：内部读取与 Agent 注入属 T-22C；提案生成 T-22D；管理端页面 T-22E；量化验收 T-22F。本轮未改任何开关，`SKILL_INJECTION_ENABLED` 仍默认关闭。
