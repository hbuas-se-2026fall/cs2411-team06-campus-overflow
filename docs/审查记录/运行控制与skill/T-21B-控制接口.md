## 决策说明

- 接口补了一个计划外的只读 `GET /api/governance/agent-runs/{id}/control`：T-21E 页面需要状态回显，写接口不足以支撑；不改变 plan 的写接口契约。
- 治理任务判定沿用 Agent 侧 `slotKindForTask` 的既有语义：`moderation_scan` 为治理任务；`chat` 需运行归属用户角色为 admin。新增任务类型时在此处扩展，不开放学生/教师会话。
- 审批等待判定使用 `moderation_cases.agent_run_id` + 未执行状态（pending/agent_proposed/manager_directed）。限制：Workflow 侧等待不经该表绑定，无法识别，留给 T-21D/T-21C 在 Agent 边界再兜底。
- `trace_id` 采用 `admin-{admin_id}`，与既有管理端处置审计一致；未透传前端 trace，避免改动现有管理端契约。
- 开关关闭时：管理端写接口 409；内部拉取返回 `enabled=false` 与空命令，Agent 保持现状继续，不因关闭控制而误停。
- 分层：新增 `repository_control -> governance.models` 合法中转边与 `service_control` 源模块，保持 lint-imports 五契约全绿。
- 遗留：Agent 侧跟随执行属 T-21C；定时清理与双实例并发 ack 属 T-21D；管理端页面属 T-21E。
