专项覆盖：

1. 假时钟：暂停超过 30 分钟本地兜底取消，抛 `pause_timeout`；
2. 后端系统取消命令（`requested_by=null`）被识别为 `pause_timeout`，管理员取消仍为 `cancelled`；
3. 惰性判定：已过期的暂停在内部 GET 时变为 `cancelled`、revision+1，并返回系统取消命令；
4. 超时收敛追加 `system:pause_timeout` 命令，重复收敛为 0；
5. 双会话对同一批命令 ack：第一个 2 条、第二个 0 条；重复 ack 幂等；
6. 事件契约不变：控制事件仍不携带步骤信息。

## 决策说明

- **原子消费**：`ack_commands` 改为单条 `UPDATE ... WHERE status='pending'`，以 `rowcount` 作为本次消费数；并发实例只有一个能更新，重复 ack 返回 0。引导正文在同一条 UPDATE 中清空。
- **超时收敛**：`expire_paused_runs` 先筛选过期候选，再逐行条件更新（状态仍为 paused 且仍过期）才追加取消命令并 revision+1；多实例定时器同时运行也只有一个能成功，避免重复取消命令。
- **读时惰性 + 定时清理**：管理端 GET、内部 GET、暂停/继续/取消、追加引导四个入口都先做当前运行惰性收敛；开关开启时应用生命周期启动 60 秒清理循环（`RUN_CONTROL_CLEANUP_INTERVAL_SECONDS`，<=0 关闭），关闭时完全不启动。
- **系统命令标识**：新增迁移 `rc02_system_commands` 允许 `agent_run_commands.requested_by` 为空，系统超时命令同时带 `trace_id=system:pause_timeout`；避免用 0 冒充用户。
- **运行记录标记**：后端只收敛控制状态与命令，不改 `agent_runs`。Agent 看到系统取消命令后抛 `RunStoppedError("pause_timeout")`，由既有 `audit.finish("failed")` 写入运行记录摘要，避免后端先置 failed 导致 Agent 收尾时状态机冲突。
- **释放占位**：Agent 取消路径沿用 T-21C 的 `onCancel` 中止运行，任务处理器返回后由子 Agent 池释放槽位；后端不直接操作槽位。
- **放弃方案**：不新增“cancelled”运行状态或 `pause_timeout` 列；不引入外部调度组件，复用应用生命周期内的 asyncio 循环。
- 遗留：未做真实 MySQL 双连接并发压测（当前以原子 UPDATE + 双会话消费测试覆盖语义）；管理端页面与开关关闭全量收口属 T-21E/T-21F。
