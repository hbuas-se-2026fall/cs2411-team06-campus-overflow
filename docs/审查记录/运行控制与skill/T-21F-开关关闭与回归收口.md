## 设计依据

- `specs/tasks.md` T-21F：关闭 `RUN_CONTROL_ENABLED` 时行为与现状一致；开启后回归预算（8 步/12 次/60 秒/180 秒）、审批与取消语义不变；status 与审查记录同步。
- `specs/plan.md` AX-R11：控制面默认关闭；关闭时 Agent 完全不轮询，网络失败保持原状态；预算与审批约束不因控制面改变。
- ADR-011：双层开关（后端 `run_control_enabled` + Agent `RUN_CONTROL_ENABLED`），默认关闭；权威状态在后端，Agent 只跟随。
- `.trae/rules/coding-style.md`：开发期只跑与改动范围相关的冒烟；全量回归交 CI；高风险路径（审批、取消、预算）测试必须存在。
- 已读实现：`agent/src/loop/run-control-gate.ts`（`isRunControlEnabled` 仅认 `"true"`、`createRunControlGateIfSupported` 在客户端缺控制方法时不建门）、`agent/src/loop/run-budget.ts`、`agent/src/types/plan.ts`（`MAX_PLAN_STEPS=8`、`MAX_TOOL_CALLS=12`）、`backend/app/modules/governance/service_control.py`（开关关闭时写接口 409、内部读返回 enabled=false）、`backend/app/main.py`（开关关闭不启动清理循环）。

## 决策说明

- **T-21F 只做验证与收口，不改实现**：关闭态由双层开关保证，前端按钮只在后端可用时才有意义；回归结果未发现需要修补的行为差异，因此不为“收口”额外加代码或兼容分支。
- **开启态用“无控制客户端”对照组**：真正接入控制客户端的场景已由 `run-control-gate.test.ts` 与 `run-control-injection.test.ts` 覆盖；本轮关注的是“开开关不影响预算/审批/取消”，故用同一批预算与取消用例在环境变量开启下再跑一遍。
- **关闭态语义**：管理端写接口 409、内部读 `enabled=false`、Agent 不建门不轮询，三条路径均由既有测试固定；清理循环在开关关闭时完全不启动（`app/main.py` 已按条件注册）。
- **放弃方案**：不新增“开关关闭”专用前端隐藏逻辑（页面只在运行详情展示，后端 409 文案已明确）；不调整预算常量或审批链路。
- 遗留：真实环境手动走查（开启开关 + 真实 MySQL/Agent 联调）随 T-21E 手动走查一并在人工审查时补；全量回归与 CI 绿仍需推送远端后确认；T-22A～F（skill 沉淀）未开始，`SKILL_INJECTION_ENABLED` 保持默认关闭。
