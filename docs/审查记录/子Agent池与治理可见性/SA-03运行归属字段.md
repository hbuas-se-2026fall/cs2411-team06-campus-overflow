# SA-03 运行归属字段与迁移审查记录

日期：2026-11-19
范围：`agent_runs` 表结构、内部运行创建接口、Alembic 迁移 `sa03_agent_run_pool`。

## 设计依据

- `specs/plan.md` AX-R09 可观测段：`agent_runs` 增加 `parent_run_id`、`actor_kind`、`slot_kind`、`slot_id`，旧记录保持 null。
- `specs/tasks.md` SA-03：内部运行/工具写入接受并回显字段，Alembic 增量迁移。
- `specs/constitution.md` C-08：运行必须可追踪；子 Agent 运行需可关联主运行。
- `.trae/rules/coding-style.md`：接口字段蛇形、写操作鉴权、迁移走 Alembic。

## 实现要点

- `AgentRun` 新增四个可空字段：`actor_kind`（main/governance/qa）、`parent_run_id`、`slot_kind`（governance/qa）、`slot_id`；`actor_kind` 与 `parent_run_id` 建普通索引。
- `parent_run_id` 不设外键：运行标识只作审计关联，保留跨服务与历史数据的可写入性。
- `RunCreateRequest` 增加可选字段与一致性校验：主 Agent 不得携带槽位；子 Agent 必须 `actor_kind == slot_kind` 且携带 `slot_id`。旧请求不带这些字段时保持原行为。
- 内部 `POST /runs` 与 `POST /user/runs` 透传字段；`AgentRunOut` 回显，管理端列表复用同一出参。
- 迁移 `sa03_agent_run_pool`（down_revision `p2_scan_worker_lease`）：加列 + 两个索引，`downgrade` 完整回收。

## 决策说明

1. 四个字段全部可空：旧运行记录、后台服务运行与尚未升级的 Agent 实例不需要回填，避免破坏性迁移。
2. 不加外键：父运行可能因历史数据或跨服务来源缺失；字段用于检索与展示，不作为强一致约束。
3. 一致性校验放在请求模型：主 Agent 带槽位、子 Agent 槽位不一致或缺少 `slot_id` 时直接 400，避免管理端串位数据。
4. 工具调用日志继续只通过 `agent_run_id` 关联，不重复存槽位字段，减少冗余。

## 遗留与限制

- Agent 服务尚未上报归属字段：`PersistentRunAudit` 与 `internal-client.createRun` 仍只传 taskType/traceId；SA-04 接入运行池视图时一并补齐。
- 未在真实 MySQL 上做并发写入压测；迁移本身已在本地 MySQL 执行成功。
- 管理端列表接口已能回显字段，但运行池页面属 SA-04。
