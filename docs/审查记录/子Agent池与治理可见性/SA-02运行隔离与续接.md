## 实现要点

- `createChildRunContext` 每次调用重新解析 principal 副本、重新调用 `createClient()`、重新构建工具表与 RunContext；检查点只提供 trace 与预算初始值。
- 工具表复用 `createRequestTools` → `createChildRegistry`：注册白名单 ∩ 角色能力 ∩ 主规则，只保留 low 风险工具；写入记忆的动作工具不在子 Agent 工具表内。
- `CheckpointStore` 按 `job_id` 隔离，最多 256 条，超出按最早写入淘汰；读写都做深拷贝，避免外部修改运行中状态。
- `ChildAgentRunner.run` 提供步骤、已提交动作、治理轮次、活动时间与安全检查点：
  - `commit(actionId, action)` 命中已提交列表时跳过并返回 `false`，恢复后不重复建单；
  - `markStepDone / isStepDone` 记录已完成阶段；
  - `setGovernanceRound` 单调增加，不因让位回退；
  - `safePoint()` 先持久化进度再调用 `lease.yieldIfNeeded()`，让位抛 `SlotYieldSignal` 由调度器按同一 `job_id` 重排。
- 让位时保留检查点；成功或非让位失败清空检查点。每次尝试新建 `agent_run_id`，trace 跨尝试保持一致。
- 预算初始值 `createToolCallBudget(initialUsed)`、`createRepairBudget(initialUsed)` 只允许从检查点恢复且受原上限约束；`createRunContext` 新增可选预算参数，既有调用不变。
- 检查点不保存对话正文、工具原始输出、凭证或个人记忆，只保存标识与计数。

## 决策说明

1. 检查点只存标识与计数，不存步骤返回值：避免把模型输出、工具原文或隐私数据写入内存副本；恢复时由任务执行入口按已完成阶段重新读取后端事实。
2. `commit` 采用“动作成功后再记标记”的至少一次语义；后端审批申请本身以 `request_id` 幂等，重复执行不会重复建单。进程崩溃时内存检查点一同丢失，不会跨重启错误跳过动作。
3. 预算与治理轮次由检查点单向恢复，调用方无法写小或扩大上限；未知来源的初始值直接拒绝。
4. 让位信号继续沿用 `SlotYieldSignal`，runner 只负责保存进度后原样抛出，不自行重排队，保持调度职责单一。
5. 子 Agent 不注册记忆写入工具，也不接收共享记忆写入接口；只读记忆可继承，作为参考不作为授权（C-07）。
