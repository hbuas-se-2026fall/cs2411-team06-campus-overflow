# SA-05 让位与终止审查记录

日期：2026-11-19
范围：调度器租约终止信号、`POST /agent/admin/pool/{slot_id}/drain|terminate`、管理端操作入口。

## 设计依据

- `specs/plan.md` AX-R09：让位把支援中的 qa 槽标记 draining，任务在安全检查点归还；终止只取消后续模型/工具调用，不回滚已由 FastAPI 执行的动作；两者写审计摘要。
- `specs/tasks.md` SA-05。
- `specs/constitution.md` C-06（高风险动作人工确认）、C-09（上下文隔离）。
- `.trae/rules/conventions.md`：管理端入口仅 active 管理员；界面文案简体中文。

## 实现要点

- `SchedulerLease` 新增 `signal`：每个运行中任务独立 `AbortController`；`scheduler.terminate(slotId)` 仅对运行中的槽位触发一次中止，不立即释放槽位。
- 执行入口合并信号：chat 的 `beginRun` 接受附加信号，任务使用 `AbortSignal.any([请求信号, 租约信号])`；中止后模型/工具调用在下一次检查点停止，已提交动作不回滚。
- 路由：
  - `POST /agent/admin/pool/:slot_id/drain`：仅 active 管理员；只允许正在支援治理的问答槽，否则 409；
  - `POST /agent/admin/pool/:slot_id/terminate`：仅 active 管理员；无运行任务或已终止返回 409；
  - 成功返回 `slot_id / action / accepted / audit_summary`，并写结构化审计日志（`agent_pool_admin_action`，含管理员 id、trace id、槽位、实例）。
- 前端运行池卡片在运行中槽位显示“让位”（仅支援槽）与“终止”；操作前 `window.confirm` 提示，终止明确告知不回滚已执行动作；成功后刷新池状态，失败显示错误。

## 决策说明

1. 让位只作用于“运行中的支援问答槽”：普通问答与治理槽不可让位，避免打断学生问答或治理主流程。
2. 终止只触发中止信号，不强行释放槽位：任务必须走进收尾（审计 failed/取消）后由调度器释放，避免并发 finish 与槽位状态错乱。
3. 审计摘要当前写结构化日志并随响应返回；后端没有通用管理员审计写入接口，未在本块新增表或接口，避免越权扩大范围。
4. 前端使用浏览器确认框而非自建弹窗：操作频率低、语义简单；终止文案明确“不回滚已执行动作”。

## 遗留与限制

- 审计摘要尚未持久化到后端数据库；如需长期留痕，应补专用内部审计接口后再切。
- 若某个执行入口不检查租约信号，终止不会强制打断，槽位会等任务自然结束；当前 chat 与结构化任务均已合并信号。
- 让位后任务按同一 job_id 重排，实际续接依赖任务执行入口的检查点实现（当前治理任务可在审计创建前让位）。
- 未做真实浏览器交互验收与多实例压测。
