# SA-04 运行池状态接口与管理端页面审查记录

日期：2026-11-19
范围：Agent 运行池只读接口、运行归属上报、前端 `/admin/agent/runs` 运行池区块。

## 设计依据

- `specs/plan.md` AX-R09 可观测与管理端：内部只读 `GET /internal/agent/agent-pool/status`（服务级鉴权）；Agent 管理路由 `/agent/admin/pool`；`/admin/agent-runs` 增加“运行池”区块，不新建前端应用。
- `specs/tasks.md` SA-04。
- `specs/constitution.md` C-08（可追踪）、C-09（上下文隔离）。
- `.trae/rules/conventions.md`：管理端视图与学生端同应用；接口蛇形；加载/空/错误状态。

## 实现要点

- Agent 新增 `routes/pool-admin.ts`：
  - `GET /internal/agent/agent-pool/status`：校验 `x-service-token` 与 `AGENT_SERVICE_TOKEN`，未配置或不匹配返回 401；
  - `GET /agent/admin/pool`：仅 `role=admin` 且 `status=active`，否则 403；
  - 两者返回 `instance_id + slots + queues`，不含对话正文、凭证或工具参数。
- 运行归属上报：`RunCreateInput` 与 `PersistentRunAudit` 支持 `actor_kind / parent_run_id / slot_kind / slot_id`；chat 上报 `qa` 与槽位，结构化任务上报 runner 的 actor 与租约槽位；后台服务运行保持 null。
- 前端 `api/agent-runs.ts` 增加 `fetchAgentPool()`，经同源 BFF `/api/agent/agent/admin/pool` 读取；`AgentRunItem` 增加归属字段。
- `AdminAgentRunsView` 增加“运行池”区块：实例标识、8 槽状态、任务标识、支援治理标记、两类队列等待数量与最长等待；运行表新增“来源”列（主 Agent / 治理子 Agent / 问答子 Agent + 槽位）。

## 决策说明

1. 内部接口不使用用户 JWT：它面向服务间只读查询，凭证走独立 `AGENT_SERVICE_TOKEN`，未配置时默认拒绝而不是放行。
2. 管理端路由不做额外开关：沿用 `/agent/admin/snapshots` 的管理员主体校验模式，避免再增加一个容易被遗忘的开关。
3. 运行归属字段由 Agent 上报、后端回显，前端只读展示；不改写历史记录，旧数据保持 `—`。
4. 运行池区块只读，不包含让位/终止；对应 SA-05。
5. 前端不轮询：进入页面读取一次，避免无意义请求；需要实时性时由后续刷新/轮询策略单独设计。

## 遗留与限制

- 运行池区块无自动刷新与手动刷新按钮，槽位状态可能滞后于页面停留时间。
- 让位/终止未实现（SA-05）。
- 工具调用仍通过运行详情页按 `agent_run_id` 查看，运池视图只到槽位与任务标识粒度。
- 未做多实例聚合；每实例返回自身快照。
