## 1. BFF 上游错误（真实缺陷，已修）

反馈：上游 503 JSON 透传内部地址，500 HTML 透传堆栈/主机；200 非 JSON 原样透传。

修改 `frontend/src/app/api/backend/[...path]/route.ts`：

- 上游任何 5xx：不读取、不透传正文，记录 `bff_upstream_error` 后返回脱敏 JSON；503 保留 503，其余映射 502。
- 上游 2xx 非 JSON 且非文件导出：视为契约异常，返回 502。
- 4xx 业务错误与 CSV 导出继续透传。

验证：`route.test.ts` 11 项通过（新增 503 JSON、500 HTML、200 text/plain 三项），`tsc --noEmit`、`eslint` 通过。

## 2. 教师认证与投票（判定为验收读事务快照）

证据内部存在矛盾：

- `PUBAPI-034` 创建问题返回 `id=1032` 成功；紧接着 `PUBAPI-054` 的数据库检查同时返回 `vote: null, question: null`。若后端确实写入，问题本身不可能查不到。
- `PUBAPI-047` 的评论却能在数据库查到，说明检查脚本部分使用新连接、部分复用了旧事务。
- 代码路径：`service.certify_answer` 调 `set_certified_flag` 后 `db.commit()`；投票按 spec E-04 toggle，重复同值即删除记录。
- 自动化：`tests/test_answer_certification.py` + `tests/test_interaction_votes.py` 共 81 项通过，均在提交后查库断言。

结论：认证/投票代码无需修改。验收脚本应在 HTTP 成功后使用**新连接且 READ COMMITTED**（或先 commit/rollback 旧事务）再查询，并按 toggle 语义断言：首次 +1、同值删除、异值改票。
