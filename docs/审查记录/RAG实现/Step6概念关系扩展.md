# Step 6 概念关系扩展

日期：2026-11-21。
状态：已实现并完成验证，待用户审查。
范围：1 跳共享受信标签扩展，每子问题最多补 1 个候选，参与精排与总预算。

## 一、设计依据

- `docs/RAG树设计与迭代记录.md` D-010：最多 1 跳，从检索命中的知识点出发，不递归；关系类型、方向、来源可追溯；扩展证据与直接召回一同参与 5→3，不绕过精排和预算。
- D-003 / D-015：保留三板块卡片与双向链接，不扩张卡片内容板块。
- D-009：每个子问题独立 5→3；跨子问题去重与总预算约束保持不变。
- D-023 / D-024：召回、精排分两段；扩展候选不直接改写 RRF 分，仍由精排统一排序。
- `.trae/rules/coding-style.md`、`.trae/rules/conventions.md`：课程权限、日志脱敏、测试与提交纪律。

链路：

```text
每个子问题：召回 → RRF → 卡片去重
  → 取首个命中卡片作为种子
  → 共享受信标签 1 跳，最多补 1 个候选
  → 直接候选 + 扩展候选 ≤ 5
  → 精排 → 阈值 → 3 张卡
  → 摘要 + 正文（扩展卡片带 relation）
```

## 三、关键决策

1. **以共享受信标签作为第一版关系来源**：当前卡片没有前置/定义/对比等显式关系字段；标签由教材或教师维护，可追溯到 `tag:<id>`，比无来源的模型生成关系更可审计。
2. **关系类型固定为 `shared_tag`、方向对称**：不伪造“前置/定义”语义；后续接入显式关系抽取时再扩展类型。
3. **每子问题只从首个命中卡片出发，最多补 1 个候选**：控制噪声与外部调用；D-010 的种子数与扩展限额此前未定，这里取最小可用值。
4. **扩展候选参与精排**：扩展块使用种子分的 0.5 倍进入候选池，但仍由精排/阈值决定去留，不直接进入最终 3 条。
5. **候选总数仍为 5**：有扩展时直接候选让出 1 个名额，保证扩展参与但不扩张总上下文。
6. **课程范围二次校验**：共享标签可能跨课程，扩展时再次检查 `courseId`，避免越权取证。
7. **关系透传**：`RagHit.relation` 同时标在扩展卡片的摘要与正文上，保留 `seedCardId/tagId/source/direction`，便于前端或审计解释“为什么出现这张卡”。
8. **不递归**：只扩展 1 跳，不沿新卡片继续扩展。

放弃的替代方案：

- 模型生成概念关系：无来源、难审阅，且需要额外模型调用与结构化校验。
- 按教材来源或相邻章节扩展：范围过宽，容易引入无关卡片。
- 扩展直接进入最终结果：绕过精排与阈值，违背 D-010 的衔接要求。
- 每种子扩展多个候选：当前没有效果数据，先限制为 1 个，避免上下文被关联卡片挤占。

## 五、限制与遗留

- 标签共现只是关系代理，不等于前置知识、定义依赖或显式对比；可能扩展出主题相近但无教学依赖的卡片。
- 每子问题只扩展 1 个候选、只从首个命中出发；种子选错时扩展无效。
- 关系为对称，未区分方向；同一标签下多张卡片时按标签遍历顺序取第一个，未做相关性排序。
- 未实现关系抽取、人工审阅与关系原文引用；D-010 的完整关系类型仍未落地。
- 前端尚未展示 `relation`，模型也只在证据中看到卡片内容，不会自动解释关系。
- 未用真实课程语料与 50 题标注验证扩展是否提升 Recall/nDCG，也未测额外延迟。
