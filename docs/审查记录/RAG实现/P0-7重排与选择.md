目标链路：

```text
两路召回（topN=20）→ RRF k=60 → 每卡最多 1 块
  → 候选 5 → /rerank 精排 → 阈值 0 → 最多 3 条
  → 总预算 2400 字 → 证据块
```

## 三、关键决策

1. **复用 OpenAI 兼容 `/rerank`**：按用户选择，不引入本地 ONNX/Transformers 运行时。请求体为 `{model, query, documents, top_n}`，只接受 `results[].index/relevance_score`。
2. **先 RRF、后精排**：精排只作用于融合去重后的 5 个候选，避免对全量召回调用外部服务，控制延迟与费用。
3. **卡片级去重**：`maxChunksPerCard` 默认 1，同一卡片的摘要与正文不会占满候选或最终名额；D-022 的“摘要 + 正文同时返回”仍未实现，单独排期。
4. **阈值默认 0 且可配**：不做硬编码“置信度”；分数量纲随模型变化，上线前需用真实 query 分布校准。低分不足 3 条时返回实际条数，不凑数；全低返回空结果，由模型决定是否拒答。
5. **总预算 2400 字**：按最终证据累加，超出截断最后一条；剩余不足 200 字时丢弃残片，避免把半句话当证据。
6. **失败降级**：超时、HTTP 非 2xx、响应格式异常回退 RRF 顺序，`rerankApplied=false` 并记录 `rerankError`；调用方取消是控制流，直接抛“检索已取消”，不降级继续执行。
7. **分数语义**：`RagHit.score` 为最终排序分（启用重排时为精排分），新增 `rrfScore` 保留融合分；两者不混用。
8. **配置无效软降级**：`RAG_ENABLED=true` 但 `RAG_RERANK_ENABLED` 配置不完整时，只记录一次 `rag_rerank_config_invalid`，索引照常构建，不让整个 RAG 不可用。
9. **日志脱敏**：不记录 query、正文、API Key；重排诊断只含课程、候选数与错误类型。

放弃的替代方案：

- 本地 Cross-Encoder：部署与内存成本更高，用户明确选择复用现有服务。
- 先精排再 RRF：精排只能看到单路结果，无法利用融合信号，且调用量更大。
- 阈值写死为 0.5：不同服务的 relevance_score 量纲不同，容易误杀，改为可配置。
- 本期同时做摘要 + 正文展开：会改变工具输出形态与评测口径，留给 D-022 单独实现。

## 五、限制与遗留

- 未用真实 rerank 服务与真实课程语料跑过；效果、P95 延迟与费用未测。
- 阈值默认 0 未校准；真实服务可能返回 logits 或 0～1 分数，需按服务商调整。
- D-022 已补：命中卡片返回摘要 + 正文（2026-11-21）；正文粒度仍为段落块，工具层单条 800 字截断保留。
- 子问题拆解、多查询聚类、概念扩展、无答案独立拒答策略仍未实现。
- 工具层仍有单块 800 字截断，与 2400 字总预算叠加；两者关系待真实上下文评估后统一。
- 50 题人工标注 pilot 与 Recall/nDCG/引用忠实度评测未执行。
