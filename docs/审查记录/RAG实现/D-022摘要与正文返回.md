# D-022 摘要与正文同时返回

日期：2026-11-21。
状态：已实现并完成验证，待用户审查。
范围：RAG 命中卡片返回 `summary` + 定位到的 `body`，工具 `limit` 改为卡片数。

## 一、设计依据

- `docs/RAG树设计与迭代记录.md` D-022：用户确认“命中后同时可以看摘要和定位到的正文片段”；返回单元包含摘要与正文，正文通过既有锚点定位，不复制知识；粒度、长度与数量原待细化。
- D-003 / D-015：保留三板块卡片与双向链接，不扩张卡片内容板块。
- D-023：召回 N → 融合去重 → 精排 3～5 → 生成；本次不改变召回数量。
- `docs/审查记录/RAG实现/P0-7重排与选择.md`：精排与卡片去重已落地，命中单元为卡片。
- `.trae/rules/coding-style.md`、`.trae/rules/conventions.md`：蛇形字段、统一响应、日志脱敏。

## 二、实现

链路改为：

```text
召回 → RRF → 卡片去重 → 候选 5 → 精排/阈值 → topK 张卡
  → 每张卡：summary + 定位 body → 总预算 2400 字
```

- `agent/src/knowledge/rag/index.ts`：
  - 构建时按 `cardId` 建立索引；
  - 选中卡片后取该卡 `summary` 与 `body`，摘要排在正文前；
  - 代表块是正文时直接使用该正文；代表块是摘要时取该卡 RRF 最高的正文，若无召回则取该卡第一个正文；
  - 预算按“摘要 + 正文”合计，正文超预算时截断，剩余不足 200 字则丢弃；
  - `topK` 表示卡片数，同一卡片不会重复计数。
- `agent/src/tools/search-knowledge.ts`：`limit` 描述改为“返回卡片数上限，每张卡片最多含摘要与正文两条”，输出字段不变。
- 测试：`rag-index` 新增摘要+正文、摘要命中展开正文、去重与预算用例；`rag-tool` 新增 `limit=1` 返回两条证据。

## 三、关键决策

1. **选择单元保持卡片**：精排与阈值仍以卡片为单位，避免摘要和正文被当成两个独立结果重复排序。
2. **摘要在前、正文在后**：符合“先看摘要再读正文”的阅读顺序，同时两者都可见。
3. **`limit` 改为卡片数**：原先“片段数”语义与 D-022 冲突；每卡最多两条，工具输出仍用 `chunk_id` 定位。
4. **分值口径**：同一卡片的两条证据共享卡片最终分（启用重排时为精排分）；`rrfScore` 保留各自融合分，`rerankScore` 只标在真正参与精排的代表块上，避免暗示摘要也被重排。
5. **正文选择**：正文命中时使用命中正文；摘要命中时优先取 RRF 最高的正文，未召回时退回该卡第一个正文，保证“定位到的正文”不会缺失。
6. **预算优先摘要**：摘要较短，先计入预算；正文放不下时截断或丢弃，避免摘要被正文挤掉。
7. **不复制知识**：返回的正文仍是既有 `chunk_id` 指向的片段，不生成第二份正文内容。

## 五、限制与遗留

- 正文粒度仍是段落块（默认 ≤1200 字），不是句子级定位；工具层继续单条截到 800 字。
- 摘要命中但正文未召回时，会返回该卡第一个正文，相关性由精排/阈值保证，未做正文级二次精排。
- 前端尚未使用 `chunk_id` 做正文锚点跳转；当前只保证接口同时返回两部分。
- 总预算 2400 字对多卡片可能不足以容纳所有正文，超出的正文会被截断或丢弃，诊断只有 `truncated`，未区分“摘要截断/正文截断”。
- 未用真实课程语料验证摘要与正文的配对质量。
