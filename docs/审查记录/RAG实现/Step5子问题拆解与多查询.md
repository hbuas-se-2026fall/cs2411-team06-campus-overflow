# Step 5 子问题拆解与多查询

日期：2026-11-21。
状态：已实现并完成验证，待用户审查。
范围：复合问题确定性拆解、每个子问题独立 5→3、跨子问题轮转合并与去重、共享总预算。

## 一、设计依据

- `docs/RAG树设计与迭代记录.md` D-008：复杂问题内部拆解为子问题，不直接拿整段问题做一次检索。
- D-009：每个子问题独立初筛 5 → 精排最多 3；最终统一去重并受总上下文预算约束，不能把“3 个”误解为全局最多 3 个，也不能让某个子问题被完全忽略。
- D-023：召回 N 与精排数分两段；本次不改变 N=20。
- D-024：不同量纲分数不直接相加；子问题合并按卡片轮转，不按分数强行归一。
- D-022：命中卡片返回摘要 + 正文；本次合并不破坏该返回单元。
- `.trae/rules/coding-style.md`、`.trae/rules/conventions.md`：默认关闭外部依赖、日志脱敏、测试与提交纪律。

链路：

```text
query
  → 拆解（≤4 子问题）
  → 每个子问题：召回 20 → RRF → 卡片去重 → 候选 5 → 精排 → 阈值 → 5→3
  → 跨子问题按卡片轮转合并
  → 跨子问题片段去重
  → 2400 字总预算
  → 每张卡：摘要 + 正文
```

## 三、关键决策

1. **确定性拆解，不新增模型调用**：按 `？?；;。！!换行` 和“以及/还有/另外/并且/同时”切分；不生成同义改写，避免无依据扩大召回或增加一次 LLM 调用。
2. **不拆“和/与/及”**：这些词常连接同一信息需求（如“死锁和事务隔离的区别”），贸然拆开会破坏对比语义。
3. **子问题上限 4**：控制 embedding 与 rerank 的放大倍数；超出部分丢弃，保持原顺序。
4. **每个子问题独立 5→3**：复用现有 `search`，不改召回与精排参数；`searchMany` 以 `min(3, limit)` 为子问题内卡片上限。
5. **轮转合并**：先取各子问题的第 1 张卡，再取第 2 张，避免第一个子问题占满全局名额；同一卡片只保留一次，片段按 `chunkId` 去重。
6. **全局上限仍是 `limit` 张卡片**：这是工具契约的硬边界；D-009 的“每个子问题 3 条”在合并前已执行，合并后受工具 `limit` 与总预算共同约束。
7. **预算最后统一裁剪**：子问题内部用 1,000,000 字符的临时上限，避免先跑的子问题挤占预算；合并后按 2400 字截断，剩余不足 200 字丢弃。
8. **诊断聚合与明细**：`subQueryCount` 记录实际子问题数；候选数、精排数、丢弃数按子问题求和；`rerankApplied` 取所有子问题成功；`rerankError` 取第一个错误。`subQueries` 按拆解顺序给出每个子问题的检索计数、合并后贡献卡片数/字符数、截断标记与错误类型，不记录子问题原文。

放弃的替代方案：

- LLM 子问题改写/多查询聚类：需要新增模型调用与结构化输出校验，当前没有真实模型联调条件，留待效果验证后再评估。
- 按全局相关性直接截断：会让第一个子问题占满预算，违背 D-009 的覆盖要求。
- 每个子问题各自保留 2400 字再拼接：总上下文膨胀到 4 倍，不符合总预算约束。

## 五、限制与遗留

- 没有同义改写、查询聚类或指代消解；“死锁和事务隔离的区别”这类对比问题仍按单查询处理。
- 子问题数量最多 4；复杂问题可能被截断。
- 每个子问题各自调用 embedding 与 rerank，最坏情况增加约 4 倍外部调用；延迟与费用未测。
- 诊断不含子问题原文；`subQueries` 只用于内部观测，不对外暴露。
- 未用真实课程语料与 50 题标注验证拆解是否提升 Recall/nDCG。
