# P2 全量扫描 worker 原子认领与租约

## 设计依据

依据用户 P1 审查意见（“为扫描任务增加跨 Agent 实例的 worker 原子认领”）、`docs/superpowers/plans/2026-11-18-下一期四阶段执行计划.md` 第三节（P2 管理员全量扫描）、`docs/后端架构/分层架构设计基线.md`（router → service → repository 分层与事务边界）、`.trae/rules/coding-style.md`（内部接口必须鉴权与测试）以及 `.trae/rules/conventions.md`（Agent 不得绕过 FastAPI 改业务数据）。

原实现只有两条保护：`active_slot` 唯一索引保证“同刻仅一个活动任务”，Agent 进程内 `activeJobs` 保证“本进程不重复启动”。二者都无法阻止多个 Agent 实例对**同一任务**各自启动 worker，从相同游标读同一页、重复调用模型与建单。

本次把执行权下沉为数据库级租约：

- 认领使用条件更新（`WHERE status IN ('queued','running') AND (worker_token IS NULL OR lease_expires_at IS NULL OR lease_expires_at <= now)`），检查与占用在同一条 UPDATE 内完成；MySQL 行锁等待后会重新判断条件，跨实例只有一个 `rowcount = 1`。
- 认领成功下发一次性 `worker_token`（fencing token）与 `lease_expires_at`；翻页、进度回写、续租都校验 token 与租约。
- 续租同样为条件更新，租约过期后旧 worker 无法自续，只能等新 worker 重新认领。
- 终态与取消清空 `worker_id / worker_token / lease_expires_at`，避免旧 token 在任务结束后继续写入。
- Agent 端在创建/恢复路由中先认领，只有拿到 token 的实例才 `start`；执行器每批与每条内容前续租，409 视为失去任务并停止，不再写任务终态。

## 决策说明

- 认领放在路由而非执行器：创建/恢复是唯一入口，先认领可立即把 409 返回给调用方；执行器只接收 token，避免“启动后再认领”期间出现两个后台循环。进程内 `activeJobs` 降级为本地幂等提示，不再承担互斥。
- 使用 `worker_token` 作为 fencing token 而非 `worker_id`：token 每次认领随机生成，旧实例持有旧 token 时即使 `worker_id` 相同也无法写入。
- 续租频率采用“每批 + 每条内容”，与既有逐条取消检查合并，不额外增加请求数量；Agent 端默认租约 120 秒（后端允许 10～300 秒），给首轮审计与上下文注入留出余量。
- 租约丢失后不回写 `failed`：任务可能已被新 worker 接管，旧实例写终态会覆盖新进度；只记录审计 run 失败摘要。
- 保留 `active_slot` 唯一索引：它解决的是“同刻只有一个活动任务”的另一类约束，与“同一任务只有一个 worker”互补，不能互相替代。
- 遗留限制：租约过期依赖各实例时钟大致一致；未引入独立的 fencing 序号列，token 值本身即单调隔离依据；MySQL 并发用例仍需在具备真实数据库的环境补跑一次。
