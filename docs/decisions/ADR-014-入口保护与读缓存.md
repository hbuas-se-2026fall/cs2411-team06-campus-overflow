# ADR-014：入口保护与热点读进程内缓存

- 状态：accepted
- 日期：2026-11-28
- 决策人：用户
- 关联：R-003 / T-23E / T-23F

## 背景

1000 并发压测显示：同步栈下 anyio 默认每 worker 40 线程与数据库连接池先饱和；10000 并发则死在入口监听队列。用户确认本期不做异步化，先做入口保护、慢查询定位与进程内只读缓存。

## 决策

1. **入口保护**：Nginx 对 `/api/` 施加每 IP `limit_conn 1000`、`limit_req 1000r/s burst=2000`，超限返回 429/503 JSON；`/internal/agent/*` 禁止公网访问；uvicorn `--backlog 4096`。
2. **热点读缓存**：课程列表核心数据、标签列表、榜单按 key 做进程内 TTL 缓存（默认 30s、LRU、线程安全、无 Redis）；课程 joined 状态与 mine 查询不走共享缓存。
3. **线程配额**：anyio 同步线程默认配额提升到 200/worker，可通过 `BACKEND_THREADPOOL_TOKENS` 调整。
4. **缓存失效**：仅 TTL 过期；写操作不主动失效；多 worker 各自独立，允许最多 30s 不一致。
5. **异步化**：不在本期实施；1000 并发 99%/1s 的验收目标未达成，需异步数据库或水平扩容另行立项。

## 后果

- 正面：100 并发成功率 100%，重复课程/标签/榜单查询减少；入口可挡住 10000 级连接洪峰。
- 负面：读数据最多 30s 陈旧；多 worker 快照不一致；缓存不能突破同步线程与数据库连接上限。
- 实测：1000 并发 75.89%（5 worker、200 线程、100 连接）；提高到 150 连接反而降到 65.22%，说明瓶颈在同步执行模型而非连接数。
- 未验证：Nginx 运行时语法与限流效果（本机 Docker 守护进程未启动）、真实 4C4G 容器。
