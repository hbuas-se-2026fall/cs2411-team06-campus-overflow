# ADR-010：计划内无依赖步骤并行执行

- 状态：accepted
- 日期：2026-11-24
- 决策人：用户
- 取代：无
- 被取代：无

## 背景

子 Agent 的计划执行是严格串行：8 步计划、12 次工具调用、单次 60 秒、整次 180 秒。复杂问答需要多关键词、多课程、多来源检索时，串行累加很容易触达 180 秒上限；治理批量扫描同样逐目标串行，吞吐受限。R-001 要求在不改变权限与成本的前提下，允许计划内无依赖的子任务与工具调用并行。

## 决策

1. **范围**：只做同一子 Agent 计划内的步骤并行；一个 job 仍只占一个槽位，不改变槽位计费、让位与检查点语义。
2. **依赖判定**：静态解析步骤参数中的 `$sN` 引用；被引用步骤构成前驱依赖，同层无依赖步骤可并发。引用不存在或成环在计划校验阶段直接拒绝。
3. **并发上限**：单计划默认 4 个在途工具调用；进程级在途调用总上限默认 12，按 4C4G 设定，可通过环境变量调整。
4. **工具边界**：仅 `riskLevel=low` 且可执行的只读工具参与并发；计划中出现 `proposeGovernance`、`proposeClassMembership`、`proposeTeachingExperience` 时整份计划回退串行，保持审批顺序与幂等语义。
5. **预算与停止条件不变**：8 步、12 次调用、单次 60 秒、整次 180 秒、返工最多 1 次均不放宽；预算在执行前同步扣减，并发不超发。
6. **失败语义延续现有实现**：普通工具失败记入 `failures` 并继续其他步骤；401/403、安全策略错误、取消、预算耗尽终止全部在途调用。
7. **审计串行**：工具执行可并行，审计事件仍经进程内串行队列写入，保证 `sequence_no` 严格递增与 `step_id` 对账；不修改后端审计协议。
8. **默认关闭**：并行由全局开关控制，默认关闭。开关存后端配置表，仅管理员可改；后端读写接口、Agent 读取通道和管理员设置页均已接入。

本期不做（登记下期计划）：多子 Agent / 跨 job 并行、写操作与审批步骤并行、并发度自适应、修改预算与恢复机制。

## 后果

- 收益：复杂检索与批量扫描的 p95 时延下降，目标为串行对比下降至少 30%；工具调用总量与权限边界不变。
- 限制：依赖分析只支持现有纯引用语法；含审批动作的计划没有并发收益；实例级信号量可能让高峰请求排队更明显。
- 未验证：后端 `/internal/agent/*` 的并发容量与审计写吞吐尚未实测，默认值与阈值需在压测后校准。
- 后续动作：补全局开关接口与 Agent 读取；做串行/并行对比压测；根据 4C4G 实测结果调整默认值。
