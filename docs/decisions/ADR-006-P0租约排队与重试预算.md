# ADR-006：P0 跨实例租约、全局问答排队与重试预算

- 状态：accepted
- 日期：2026-11-21
- 决策人：用户
- 取代：P0-1 早期“同实例即可回收未过期槽位”的规则
- 被取代：无

## 背景

多实例部署下，本地槽位无法限制全局并发；同一实例的多个请求还会互相顶替租约。问答超限不应立即返回繁忙，而应跨实例排队。

## 决策

- 槽位租约以 `(kind, slot_no)` 为主键，带 `fencing_token` 与过期时间；claim / renew / release 均校验 token。
- 回收条件收紧为：租约已过期，或同一 `job_id` 的重试；同实例不同 job 不得顶替。
- 全局问答超限进入跨实例 FIFO 排队；队首未过期 waiter 才能晋升；过期 waiter 机会式删除。
- 重试预算初始 5；每次顶替/重试 -1；归零后不可顶替、不可重试、不可新开槽位；过期且被其他 job 接管时视为新任务，预算重置为 5。
- 全局问答配额由 `AGENT_GLOBAL_QA_LIMIT` 控制，默认 0（不启用）；排队等待计入运行预算。

## 后果

- 同 job 跨实例可立即接管，代价是消耗 1 次预算。
- 显式 release 会删除租约行，同一 job 再次 claim 会重新获得 5 次预算；当前不跨 release 累计。
- 两台主机共用同一 `AGENT_INSTANCE_ID` 属配置错误，可能互相顶替。
