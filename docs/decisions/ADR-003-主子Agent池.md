# ADR-003：主 Agent 编排 + 子 Agent 池

- 状态：accepted
- 日期：2026-11-19
- 决策人：用户
- 取代：单 Agent Loop 作为唯一执行形态
- 被取代：无

## 背景

治理任务与学生问答共享一个 Agent 时，长任务会阻塞问答，且任务间上下文容易串联。需要可隔离、可限流、可观测的执行单元。

## 决策

- 每实例最多 8 个子 Agent：3 个固定治理槽 + 5 个学生问答槽。
- 问答槽空闲时支援治理；治理积压不得饿死问答。
- 子 Agent 为同进程逻辑隔离执行单元，不共享任务间可变上下文、凭证、会话或工具授权；槽位复用必须整体重建。
- 外部命令、浏览器、MCP、文件执行统一走沙箱。
- 主 Agent 是共享记忆唯一写入方；子 Agent 只接收最小必要上下文并回传摘要。
- 管理端可见池状态、子 Agent 运行/工具调用，并支持让位（drain）与终止（terminate）。

## 后果

- SA-01/02B/06 已落地；SA-03/04/05 待生产验收。
- 真实模型并发、跨实例容量与审计摘要持久化仍未验证。
