# ADR-012：运行时缺陷修复（生产密钥、多 worker 容量、BFF 网关错误）

- 状态：accepted（第 1 条 worker 上限部分被 [ADR-013](./ADR-013-worker运行时探测.md) 取代）
- 日期：2026-11-27
- 决策人：用户
- 关联：requirements/R-003、BUG-001 / BUG-002 / BUG-003

## 背景

压测暴露出三项运行时问题：SQLAlchemy 默认连接池（size=5 / overflow=10）在 100 并发下耗尽；生产 Compose 在缺少环境变量时回退到开发默认 JWT 密钥与 root 密码；BFF 上游连接失败或超时未映射网关错误，直接返回 500。

## 决策

1. **多 worker + 按资源分配连接池**：后端以多进程运行。worker 数取 `min(4, CPU 核数 // 2, 内存 GB)`，至少 1，允许 `WEB_CONCURRENCY` 覆盖；每 worker 连接池 `pool_size=10`、`max_overflow=10`，合计连接数不超过 4×20=80，为 MySQL 默认 `max_connections=151` 留出迁移与运维余量。`pool_timeout=5s`，池等待超时映射为 503，不再表现为客户端超时。
2. **生产密钥启动门禁**：生产（`debug=False`）启动时强制校验 JWT 密钥为非默认且 ≥32 字节、数据库密码非空/非 `root` 且 ≥12 字符；不满足直接抛 `ValidationError`，容器启动失败。Compose 对 `MYSQL_ROOT_PASSWORD` 与 `BACKEND_JWT_SECRET` 使用 `${VAR:?}` 必填语法，缺失时 `docker compose config/up` 即失败。本期不强制切换非 root 数据库账号，保留为后续加固项。
3. **BFF 网关错误契约**：上游 `fetch` 设置宽松超时（普通接口 60s、导出接口 300s），并通过多 worker/多线程扩容避免正常请求触达超时；连接拒绝/DNS 等网络错误返回 502，真实挂起返回 504。响应统一为 `{code,data,message}`，带 `x-trace-id` 与 `retry-after`，不泄露上游地址、堆栈或 SQL。
4. **验收口径**：100 并发持续 60s，成功率 ≥99%、P95 ≤1.5s、0 条连接池超限；弱密钥/缺密钥必须启动失败；上游拒绝与超时必须分别返回 502/504。

## 后果

- 正面：高并发下连接不再被 15 个连接卡死；伪造 JWT 失去默认可乘之机；前端可区分网关错误并重试。
- 负面：多 worker 增加内存占用与连接总数，需要按实例资源与 MySQL 上限核算；已有本地 `.env` 含弱值时升级后会启动失败（预期安全行为）。
- 边界：不改造全异步数据库访问；不引入 Docker secrets / 云密钥管理；不强制非 root 数据库账号；不改后端正常 4xx/5xx 语义。

## 备选方案

- 仅调大单 worker 连接池：CPU 利用不足，100 并发仍受单进程线程池限制，否决。
- BFF 完全不设超时：上游挂死会长期占用 BFF 线程，否决。
- 只靠 Nginx 超时：BFF 内仍无法给前端统一错误码，且本地开发无 Nginx，否决。
- 生产仍允许默认密钥并仅打印警告：无法阻止伪造 JWT，否决。
