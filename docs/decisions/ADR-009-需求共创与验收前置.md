# ADR-009：需求共创与验收前置

- 状态：accepted
- 日期：2026-11-21
- 决策人：用户
- 取代：直接从任务号开工的做法
- 被取代：无

## 背景

用户不习惯一次写完整需求模板，过去的流程常从“进入 P0-X”直接开工，验收标准在实现后才补齐，导致范围靠猜、返工与文档漂移。

## 决策

- 每个新需求默认进入“需求共创对话协议”：助手先复述与做可行性初判，再按七问逐项 grill，用户回答，助手整理成 `specs/requirements/R-XXX-<slug>.md`。
- 七问固定为：目标与场景、范围（做）、非范围（不做）、验收标准、约束、依赖与风险、优先级与决策。
- 需求简报确认前不写代码、不建任务；未决项必须显式记录为风险与默认假设。
- 仅文档错字、单行修复可在用户明确说“跳过七问”时走轻量通道，并记录豁免。
- 实施后用固定格式反馈，逐条对照验收，不再用“已完成”概括。

## 后果

- 每个需求前置对话变长，但返工与验收争议减少。
- 助手承担模板整理工作，用户只需回答与确认，便于形成习惯。
- 该协议与模板可在项目结束后抽成独立工作流模板。
